# 业务流程

## 1. 当前角色与职责

当前系统已实现四类单一岗位角色，角色由管理员通过用户管理页面或 API 分配：

| 角色 | 当前可执行工作 |
| --- | --- |
| `ADMIN` | 用户/角色管理以及全部仓储查询和操作 |
| `WAREHOUSE_MANAGER` | 全部仓储查询；基础资料、入库、库存调整/移库、出库操作 |
| `RECEIVER` | 全部仓储只读查询；入库建单和分批/整单收货 |
| `PICKER` | 全部仓储只读查询；出库建单、库存分配和发运 |

权限由 API 网关和仓储服务分别按请求方法和路径执行；仓储服务直连也会解析 JWT，并以令牌身份覆盖来路不明的 `X-User-*`。前端菜单与按钮会同步隐藏无权能力，但不能代替服务端授权。当前尚未实现一人多角色、仓库级数据范围、权限点配置和审批权限。

## 2. 入库流程

```mermaid
flowchart LR
    A["RECEIVER / 主管创建入库单"] --> B["校验启用的仓库、供应商与 SKU"]
    B --> C["PENDING 待收货"]
    C --> D["指定或选择启用收货货位"]
    D --> E["锁定单据、货位与库存维度"]
    E --> F["增加库存余额"]
    F --> G["追加 INBOUND 流水"]
    G --> H["RECEIVED 已收货"]
```

当前规则：

- 入库单包含仓库、供应商、预计到货时间及一条或多条 SKU 明细。
- 收货支持按明细登记本次实际数量：`PENDING → PARTIALLY_RECEIVED → RECEIVED`。
- 收货货位可由请求指定；省略时优先选择启用的 `RECEIVING` 货位，再选择仓库首个启用货位。
- 相同仓库、货位、SKU 和批次只能对应一个库存余额；相同批次已存在时有效期必须一致。
- 收货事务同时更新实收数量、库存余额、库存流水和单据状态，失败时整体回滚。
- 创建与收货均支持 `Idempotency-Key`。网络重试必须复用原键，避免创建重复单据或重复入账。

质检、拒收、供应商差异归责与独立上架任务仍在路线图中。

## 3. 出库流程

```mermaid
flowchart LR
    A["PICKER / 主管创建出库单"] --> B["PENDING 待分配"]
    B --> C["锁定订单与可用库存"]
    C --> D["过滤过期批次和停用货位"]
    D --> E["按 FEFO 分配"]
    E --> F["ALLOCATED 已分配"]
    F --> G["锁定分配余额并确认发运"]
    G --> H["扣减实物量和已分配量"]
    H --> I["追加 OUTBOUND 流水"]
    I --> J["SHIPPED 已发运"]
```

当前规则：

- 出库单包含仓库、客户、要求发运时间和一条或多条 SKU 明细。
- 主状态流为 `PENDING → ALLOCATED → PICKED → PACKED → SHIPPED`，越级或重复流转返回冲突。
- 分配量不能超过可用量 `quantity - allocated_quantity - locked_quantity`。
- 指定批次时只从该批次分配；未指定时按“最早有效期优先、无有效期最后、余额 ID 稳定排序”的 FEFO 策略分配。
- 有效期早于当天或货位状态非 `ACTIVE` 的库存不参与分配。
- 分配只增加预占量；发运才同时减少实物量和预占量，并追加负向库存流水。
- 创建、分配和发运都支持 `Idempotency-Key`，可安全重放同一请求结果。

待发运状态可取消并释放预占；已发运订单可整单退货并追加正向库存流水。部分发运、部分退货、独立拣货任务分派和扫描复核仍在路线图中。

## 4. 库存作业

### 4.1 库存调整

只有 `ADMIN` 或 `WAREHOUSE_MANAGER` 可以调整库存。调整数量是带方向的增量；服务端锁定对应维度，禁止调整后出现负库存或“预占＋锁定大于实物量”，并追加 `ADJUSTMENT` 流水。请求可提供原因，省略时记录“手工库存调整”；客户端应携带幂等键。

### 4.2 移库

移库在一个事务内执行：

```text
校验同仓不同货位 → 按 ID 顺序锁定源/目标货位
→ 锁定源余额和目标库存维度 → 扣减来源 → 增加目标
→ 追加 TRANSFER_OUT 与 TRANSFER_IN 两条流水 → 提交
```

源库存必须有足够可用量，源和目标货位都必须启用且属于同一仓库。并发创建同一目标余额时由货位锁和维度唯一约束避免重复行。

### 4.3 库存流水查询

库存流水是只追加的业务账本。管理端库存页面可以打开流水抽屉，按关键字、仓库、流水类型分页检索。流水记录业务引用、SKU、批次、货位、带方向数量、操作人和发生时间，不能通过 API 删除或修改。

### 4.4 尚未实现

当前支持无预占库存的单维度即时盘点并记录差异流水。多人范围盘点、冻结/解冻、报损审批、补货任务和可配置库存状态尚未实现。

## 5. 幂等处理

以下命令已接入数据库幂等记录：

- 创建入库单、确认收货；
- 库存调整、库存移库；
- 创建出库单、库存分配、确认发运。

调用约定：

1. 客户端为一次业务意图生成不超过 128 个字符的 `Idempotency-Key`。
2. 超时或网络中断后重试时，保持请求内容和键不变。
3. 服务端以“操作类型＋键”为唯一范围，并校验请求 SHA-256 摘要。
4. 相同请求返回首次保存的结果；同键不同内容返回 `409`；执行中的同请求返回处理中冲突或在并发提交后重放结果。

管理端 Axios 拦截器会为写请求自动生成 UUID。第三方系统必须自行持久化原键，不能在每次重试时生成新键。

## 6. 并发与一致性

| 场景 | 当前保护 |
| --- | --- |
| 同一订单重复收货/分配/发运 | 单据悲观锁＋状态机＋幂等结果重放 |
| 同一库存维度并发增加 | 库存维度锁；新行通过货位锁和唯一约束串行化 |
| 多订单争抢库存 | 候选余额悲观锁＋事务内可用量复核 |
| 移库与分配并发 | 稳定顺序的货位/库存行锁＋负库存校验 |
| 相同写请求并发到达 | 幂等表 `(operation, idempotency_key)` 唯一约束 |
| 应用校验遗漏 | V3 数量、状态 CHECK 约束和库存流水外键 |

应用返回冲突或数据库死锁时，调用方只能在保持相同幂等键的前提下有限重试，并记录业务单号用于排查。

## 7. 用户生命周期

```text
ADMIN 创建用户并分配一个角色 → ACTIVE 可登录
→ 连续失败达到阈值后 LOCKED → 锁定期结束或管理员重置/启用
→ DISABLED 停用后拒绝登录
```

- 初始或重置密码必须为 8～72 位，并包含大小写字母、数字和特殊字符。
- 管理员不能停用自己或移除自己的管理员角色。
- 系统至少保留一名启用的管理员。
- 列表支持按用户名/姓名、状态和角色进行数据库分页查询。

## 8. 异常处理原则

| 异常 | 处理原则 |
| --- | --- |
| 登录失败过多 | 返回 `429`，等待锁定期结束或由管理员处理 |
| 未认证/无权限 | 分别返回 `401` / `403`，不依赖隐藏菜单保护 |
| 重复请求 | 使用原 `Idempotency-Key` 重放；不得用新键盲目重试 |
| 同键不同内容 | 返回 `409`，调用方检查业务意图 |
| 库存不足或状态错误 | 回滚事务并返回 `409`，不产生部分流水 |
| 主数据停用/过期库存 | 拒绝新业务或排除分配，保留历史记录 |
| 已完成业务录错 | 待发运出库可取消，已发运可整单退货；其他场景仍需受控处理，不删除原流水 |

## 9. 后续业务路线图

优先顺序建议为：质检与上架、部分发运/退货、范围盘点与冻结、PDA 条码作业、波次补货、序列号与多货主、仓库级数据权限和审批流。
